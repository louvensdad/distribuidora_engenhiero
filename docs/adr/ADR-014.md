# ADR-014: Spring JDBC explícito em vez de ORM na fundação

Data: 14/11/2026. Estado: ADOTADA.

## Contexto
Regras de estoque/dinheiro exigem transações, bloqueios e SQL previsíveis; entidades de persistência não podem
vazar como DTO público (arquitetura/01).

## Decisão
Usar `JdbcClient` com SQL explícito por módulo e records Java como modelos internos. Migrations com Flyway.

## Consequência
Mais SQL escrito à mão, porém sem lazy loading, sem dirty checking implícito e com locking explícito
(`SELECT ... FOR UPDATE`) nas fases de estoque. Revisitar se o volume de CRUD justificar.
